# 菜單 OCR 評測

`tests/` 裡的測試把 vision 呼叫全部 mock 掉了，所以**測試全綠不代表辨識是對的**。
這個目錄補上那一塊：拿標好答案的真實照片實跑，算出分數。

有了分數，「換模型有沒有比較好」「切塊改法有沒有比較好」才有辦法回答，
不用靠感覺。

---

## 你要做的事：標註

每個案例是兩個檔案，放在 `cases/`，主檔名要一樣：

```
cases/
  doumen.jpg              ← 照片
  doumen.expected.json    ← 你手工標的正確答案
```

答案檔格式：

```json
{
  "restaurant_name": "斗六門當歸鴨",
  "items": [
    { "name": "當歸鴨麵線", "price": 70 },
    { "name": "鴨肉飯（小）", "price": 40 },
    { "name": "燙青菜", "price": 30 },
    { "name": "時價海鮮", "price": null }
  ]
}
```

標註規則：

- **照菜單上印的字抄**，不要自己改寫或簡化。評分是比對字串。
- `price` 用數字。菜單上沒印價格（時價、需詢問）就填 `null`。
- `restaurant_name` 填照片上實際看得到的店名。照片裡看不到店名就整個欄位省略，
  評分會跳過店名這項。
- **要標完整**。漏標的品項會被算成「模型多抓的」，分數會失真。
- 品項數不用多，5 張照片、每張 20-40 項就足夠看出模型差異。

挑照片的原則：挑**你實際會遇到的**。手機斜拍、反光、直式長條菜單、
手寫改價、木牌黑板各來一張，比五張漂亮的正面照有用得多。

## 跑

```bash
# 1. 先檢查格式，不打 API
.venv\Scripts\python.exe evals\menu_ocr\run_eval.py --dry-run

# 2. 跑現在的設定，存成 baseline
.venv\Scripts\python.exe evals\menu_ocr\run_eval.py --label baseline

# 3. 改一個變數再跑
.venv\Scripts\python.exe evals\menu_ocr\run_eval.py --model qwen2.5-vl --label qwen

# 4. 比較
.venv\Scripts\python.exe evals\menu_ocr\run_eval.py --compare baseline qwen
```

一次只改一個變數，否則分數變了也不知道是誰的功勞。

### 可以掃的參數

| 參數 | 用途 |
| --- | --- |
| `--model` | 換 OCR 模型 |
| `--verify-model` | 換最終校對模型 |
| `--fast` | 開 `VISION_FAST`，跳過總覽那一輪 |
| `--tile-overlap 0.2` | 切塊重疊比例。直式菜單被切斷時調這個 |
| `--tile-threshold 1200` | 多大的圖才切塊 |
| `--jobs 3` | 同時跑幾個案例（預設 1，避免打爆學校 API） |
| `--verbose` | 印出完整的漏抓與錯字清單 |

## 看分數

```
案例                     召回    精確    價格      秒  店名
------------------------------------------------------------------
doumen                  62.5%   88.9%   80.0%    41.2  ✓ 斗六門當歸鴨
```

- **召回率** — 菜單上的品項有多少被抓到。**低就是漏抓**，最該優先修的指標。
- **精確率** — 抓到的品項有多少是真的。低代表在幻覺，編出菜單上沒有的菜。
- **價格正確率** — 配對成功的品項裡，價格讀對的比例。
- **店名** — ✓ 認對、✗ 認錯、`-` 這個案例沒標店名。

報表後面會列出**漏抓了哪些**、**多出哪些**、**哪些價格讀錯**。
這比總分更有用——例如漏抓的全部集中在圖片某一側，那就是切塊切壞了；
漏抓的分散且成塊消失，通常是那一塊的 JSON 被截斷。

## 注意

- 這支 script **會真的打 API 燒配額**。每張照片約 5-6 次呼叫，
  跑之前 `--dry-run` 會先告訴你總共幾次。
- **不要進 CI**。需要 API 金鑰、會花錢、而且結果本來就有隨機性。
- `runs/` 是執行紀錄，不進版控。
- 照片如果有隱私考量（例如拍到店家或人），就不要 commit `cases/`，
  改成各自在本機保存。
